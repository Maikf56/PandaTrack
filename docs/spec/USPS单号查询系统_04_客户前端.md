# USPS 单号查询系统 04：客户前端与交互界面

> 客户前端独立域名：`pandatrack.ginzavog.com`。管理端使用另一个独立域名 `pandaadmin.ginzavog.com`，两者不共用登录入口、Cookie 范围和导航。
>
> 2026-11-19 增补（裁定见 11 号文档 H1）：前端源码位于仓库独立主目录 `frontend/client`（管理端后续为 `frontend/admin`，见 10 号文档），构建产物为纯静态文件，可独立于后端服务器部署（部署形态见 01 §3.2.1）。前端获取数据的唯一通道是 `/api/v1/*` + SSE，不直接访问任何数据库。

## 1. 模块目标

为客户提供清晰、稳定、低学习成本的真实 USPS 物流跟踪工作台：客户在首页粘贴或上传单号后直接开始查询，系统一次完成清洗、计费、受理和入队；客户随后查看异步进度、真实物流状态和完整轨迹，并在参考记录、分组和导入任务中找回结果。

本模块的核心交互原则是：

1. **首屏直接查询**：参考竞品，客户看到的是“输入单号 → 开始查询”，没有独立的预览或报价确认步骤。
2. **费用规则前置、结果后置**：提交页常驻显示“1 个新单号扣 1 积分、30 天内重复免扣、无效项不扣费”等固定规则；实际扣费明细由提交结果返回，不在提交前生成报价单。提交前可通过服务端预估接口展示实时解析与预估消耗（不入账、不构成报价，见 §5.4 与 09 §5.2.1）；预估与实际扣费不一致时以受理结果为准。
3. **受理与出结果分开表达**：点击查询后先显示“已受理”和本次实际扣费，再显示后台查询进度；不得把等待状态伪装成已取得轨迹。
4. **服务端决定业务结果**：前端只展示服务端返回的清洗分类、扣费、状态和权限结果，不在浏览器内自行判断单号是否合法、是否重复、是否收费或是否已终态。
5. **批量任务化**：当前单次受理上限为 1,000,000 个候选；大批量进入任务/批次视图，按进度、分组和导出任务查看。竞品的 5 万即时结果作为前端分组呈现参考，本版百万级任务走导入任务页查看进度，不承诺即时返回全部结果。
6. **真实结果与模拟结果绝不混淆**：正式客户界面不展示模拟轨迹；开发、CI 或隔离验收若使用模拟数据，必须在页面顶部、结果卡片和详情中明确标记“模拟数据/仅测试”。
7. **异常要告诉客户下一步**：积分不足、超出单次上限、服务暂时不可用、部分结果已完成、暂未获取等情况均需给出白话说明和可执行动作。
8. **后台静默保鲜 + 客户触发式呈现**：后台按状态分层抓取非终态并静默入库；前端不推送物流状态、不弹通知、不自动改行。客户提交、打开批次或点「检查更新」时才读取最新投影。
9. **fresh 命中不制造假动作**：服务端判定无需上游请求时，前端仍可完整显示检查动作的状态反馈，但文案不得暗示刚访问过 USPS；不显示「下次自动更新 X」「查询次数」「重试次数」。
10. **规则即交互**：确认、防呆、引导和状态变化反馈做进界面，而不是写进帮助文档让客户自己读（吸收 FrogTracking 交互优化方案的核心结论，见 §3.1）；大批量防呆确认、检查更新默认勾选异常态、状态跃迁高亮与变更摘要条、新手引导均按此原则落地。

### 2.2 不包含

不包含前端计算清洗规则、积分、计费窗口、Provider 速率、浏览器环境、代理、采集端点或权限判断；所有业务判断由后端完成。前端不得显示 USPS 上游地址、Provider 名称、代理信息、profile、A 库表名、内部错误堆栈或内部服务地址。

## 3. 竞品参考与本系统取舍

### 3.1 已观察到的可借鉴交互

根据 `开发文档/02_辅助资料/同类竞品.txt` 中记录的 `frogtracking.cn` 亮点，以及 17TRACK 首屏布局，提炼以下本版要吸收的交互（原引用路径 `03_原始资料/` 不存在，D4 裁定见 11 号文档）：

> 2026-11-19 增补：竞品 FrogTracking 的交互设计分析与可点击优化原型（`开发文档/02_辅助资料/FrogTracking交互设计分析与优化方案.md`、`FrogTracking优化原型.html`）已评审。其"规则即交互"优化项按本节与 §4.4、§5.4、§5.6、§8.2、§5.13 吸收：实时解析面板 + 成本预估条、大批量防呆确认、状态跃迁高亮与变更摘要条、检查更新默认勾选异常态、可见性感知轮询与连接状态指示器、新手引导与设计系统。裁定见 11 号文档 G2。

- **直接查询**：竞品没有独立预览动作，首页是“粘贴/上传单号 → 查询”；本系统取消客户可见的 preview 步骤。
- **大批量分路径**：竞品支持手动输入和文件上传，5 万条以内直接显示结果，5–100 万进入导入任务页看进度；本版单次受理上限对齐为 1,000,000 条，按“即时结果 + 导入任务 + 导出任务”组织大批量交互。百万条任务进入导入任务页看进度，前端不承诺一次性渲染或即时返回全部结果。
- **目标组与默认组**：每批查询自动归入可改名的默认组，客户也可手动创建目标组；组和批次都保留参考记录，便于后期查阅。
- **轨迹与翻译**：批次结果可整体导出，物流轨迹可查看并在后续版本接入翻译；本版先实现轨迹时间线和导出任务，翻译作为后续增强项，不由前端伪造。
- **状态标签齐全**：签收、运输中、派送中、到达待取、已揽收、已下单、未找到、异常、邮资未付、投递失败、退回等标签纳入客户状态字典。
- **查询统计与积分明细**：客户能看历史查询汇总，也能看积分余额、冻结、消耗和流水。
- **设置与详细使用指南**：个人设置、安全设置、输入方式、计费规则、状态解释、导出和分组说明都放在客户能找到的地方。

### 3.2 不直接照搬的部分

- 不复制竞品品牌、配色、文案、页面源码或图片资源。
- 不照搬“查询完成”的假设；本系统必须明确区分“已受理”“查询中”“已获取结果”和“暂未获取”。
- 不把上游查询地址或“查看官网原文”深链放进客户前端，避免暴露数据源和绕过系统的路径。
- 不在前端承诺固定完成时间、固定并发量或“不会被限制”。
- 不把竞品公开页面的价格、状态枚举或接口行为当成本系统服务端契约；本系统以 06 计费模块、09 接口契约和实际 API 响应为准。

### 3.3 本系统的交互差异化

1. **查询可回溯**：临时快查不只保留最近一次，成功受理后仍进入客户自己的操作记录和结果列表。
2. **结果新鲜度透明**：每个结果显示取得时间、最近有效更新时间、是否沿用旧结果和时间置信提示。
3. **失败不伪装成功**：服务暂停、挑战、明确拒绝或暂未取得结果时，显示可理解的状态，不返回模拟轨迹填空。
4. **提交后费用透明**：点击查询即完成受理，返回结果中显示本次实际扣费、免扣数量和未计费数量；不设单独预览和报价确认。
5. **大批量可观察**：批量任务显示总量、已完成、处理中、暂未获取、失败待处理、当前批次和更新时间，并自动归入默认组。

## 4. 信息架构与页面布局

### 4.1 公共区导航

公共区采用轻量导航，避免客户在未登录时看到后台术语：

- 品牌 / 首页
- 产品说明
- 积分套餐
- 帮助中心
- 登录
- 申请试用（主按钮）

移动端收纳为品牌、登录和菜单按钮；菜单展开后显示其余链接。首页主任务永远是输入单号，不用轮播图、复杂营销弹窗或强制注册流程阻断查询入口。

### 4.2 工作台导航

登录后采用“左侧导航 + 顶部账户栏 + 主内容区”的结构，移动端改为顶部菜单或底部导航：

- **查询**：工作台、提交单号、临时快查、查询统计
- **记录**：结果列表、组与批次、提交记录、导入任务、导出任务
- **账户**：积分中心、设置
- **帮助**：使用指南、关于

顶部账户栏固定显示：客户名称、积分余额、账户状态、帮助入口和退出登录。余额显示来自服务端，不允许前端本地计算或乐观扣减。

### 4.3 通用页面骨架

每个工作台页面按以下顺序组织：

1. 页面标题：说明当前任务，不使用内部模块名。
2. 一句页面说明：告诉客户当前页面能做什么。
3. 主操作区：一个明确的主按钮，避免同权重按钮过多。
4. 筛选 / 查询区：仅在结果列表、操作记录和作业页显示。
5. 内容区：卡片、表格、时间线或进度面板。
6. 状态区：加载、空数据、错误、权限不足和服务暂停状态。

桌面端内容区建议最大宽度 1,280px；详情页采用“摘要卡 + 事件时间线”，批量页面采用“摘要栏 + 列表/表格”。不使用必须横向滚动才能阅读的核心信息布局。

## 5. 页面交互设计

### 5.1 首页：粘贴单号即开始

**首屏结构：**

1. 标题：“查询 USPS 包裹”。
2. 多行输入框：支持一行一个单号，也支持直接粘贴批量文本。
3. 辅助说明：“支持一次输入多个单号，每行一个；1 个新单号扣 1 积分，30 天内重复免扣，无效项不扣费。”
4. 主按钮：“开始查询”。
5. 次级入口：“查看产品说明”“查看帮助”。
6. 结果真实性说明：正式环境只展示已取得的真实结果；开发或验收页面若使用模拟数据，必须显著标记。

**交互规则：**

- 空输入点击按钮：输入框获得焦点并提示“请输入至少一个单号”。
- 输入框只做长度和空值保护，不在前端判定 USPS 格式、不自动删除内容、不静默截断。
- 未登录客户点击“开始查询”：保留输入内容，跳转登录，并在登录成功后回到原提交路径。
- 已登录客户点击“开始查询”：直接进入 `/quick` 或 `/submit`，提交请求由后端一次完成清洗、计费和入队。
- 粘贴超大文本时显示已接收字符/行数的客户端保护信息，但最终上限以服务端响应为准。

### 5.2 登录与会话恢复

- 登录页只保留邮箱、密码、登录按钮、忘记密码和申请试用入口。
- 登录失败显示白话错误，不显示“用户不存在”“数据库错误”等内部信息。
- 从受保护页面跳转登录时，成功后回到原页面或原提交草稿；草稿仅保存在当前浏览器内存或受控临时存储中，不发送第三方。
- 会话过期时弹出一次“登录已失效，请重新登录”，保留未提交的输入内容；禁止重复弹窗和循环跳转。
- 改密码或管理员撤销会话后，当前页面清理敏感会话状态并回到登录页。

### 5.3 临时快查：少量单号的快速路径

临时快查是首页主路径进入的轻量页面，仍走正式提交接口，不建立绕过计费和权限的特殊接口。

页面结构：

- 顶部：输入框、单号数量提示、清空按钮。
- 中部：固定费用规则说明。
- 底部：“开始查询”主按钮、返回工作台按钮。

流程：

```text
输入单号
  → 点击开始查询
  → 后端一次完成清洗、计费、入队
  → 返回 202、操作 ID 和本次实际扣费
  → 显示受理卡和“查看进度”
  → 查询完成后显示结果卡/详情
```

点击“开始查询”即正式提交并可能扣费；按钮下方必须写明费用规则。提交成功后即使客户关闭页面，任务仍由后台继续，之后可从提交记录、默认组和结果列表找回。

### 5.4 提交单号：直接提交与受理结果

提交页支持两种输入方式：

- 直接粘贴多行文本。
- 上传受支持的文本/表格文件，由导入任务接口处理。

页面只做两步，不设置预览和报价确认：

#### 第一步：输入与规则说明

- 输入框或文件选择区占据主要区域，显示已输入行数、文件名和移除文件操作。
- **实时解析面板**（输入即算，防抖 300ms 调用服务端预估接口 `POST /api/v1/submissions/estimate`）：
  - 总行数 N / 去重后 M / 分类分布（有效、免扣、重复、识别失败等）。
  - 识别失败清单内联展示（折叠），可一键复制；不弹窗打断输入。
  - 解析面板是**输入辅助展示，不是预览步骤**：最终分类与扣费以 202 受理结果为唯一权威。
- **成本预估条**（固定在主按钮旁）：显示“将新增 X 单 · 预估消耗 X 积分 · 其中 Y 单 30 天内免扣”，并常驻标注“预估，以提交结果为准”。预估消耗大于可用余额时主按钮禁用并显示缺口数值，而不是提交后才失败（缺口来自服务端余额快照，不由前端计算）。
- **大批量防呆确认（非报价确认）**：单次输入超过 1,000 条或选择非默认目标组时，点击提交先弹出确认卡，显示目标组名称、条数与预估积分，明确确认后才真正提交；该确认不产生报价、不计费、不入账，小批量默认组提交不弹。
- 常驻费用规则：1 个新单号扣 1 积分；30 天内同客户同单号免扣；重复项和格式错误项不扣费；单次上限 1,000,000 条，上传文件 ≤64 MB。
- 主按钮为“开始查询”，旁边写明“点击后即提交并按规则扣费”。
- 余额不足、超出上限或文件格式不支持时，主按钮保留但点击后返回明确错误；不清空已输入内容。

#### 第二步：受理结果

收到 `202` 后显示受理卡：

- “已受理”主状态。
- 操作 ID 和自动归入的默认组名称。
- 总条数、批次数、实际扣费积分。
- 可计费、免扣、重复、不可计费数量。
- “查看进度”“继续提交”“返回工作台”按钮。
- 说明：“查询结果将在后台逐步更新；关闭页面不会取消任务。”

前端可折叠查看分类明细，但只在提交成功后展示服务端返回的实际结果，不在提交前生成报价单。分类原因使用白话文案，例如“重复输入”“暂不支持的格式”“内容无法安全识别”，不直接展示内部错误码。

禁止在此时显示“已完成”“全部成功”或虚构任何轨迹事件。提交失败且未产生操作时不扣费；已产生 `202` 后网络重试必须复用同一幂等键，不重复扣费。

### 5.5 工作台首页

工作台首页参考竞品的状态汇总思路，但将信息分为“现在需要关注什么”和“我刚才做了什么”：

**第一行摘要卡：**

- 当前积分余额。
- 处理中操作数。
- 异常或暂未获取数量。
- 已完成操作数。

**第二行主操作：**

- “提交单号”主按钮。
- “临时快查”次按钮。
- 最近一次操作进度卡。
- 查询输入框快捷入口。

**第三行：**

- 最近操作列表：时间、条数、状态、扣费、查看进度。
- 结果状态分布：仅展示客户可见状态，不展示 Provider、队列或 Worker 信息。

空状态文案：

> 还没有查询记录。先粘贴 USPS 单号并开始查询，提交后这里会显示本次实际扣费和进度。

### 5.6 结果列表

结果列表是客户长期查看和筛选的主页面，不把一次提交结果限制在临时弹窗中。

**筛选项：**

- 单号搜索。
- 客户可见状态：提交已受理、查询中、已获取结果、暂未获取。
- 更新时间范围。
- 所属组/批次。
- 是否有异常提示。

**列表行/卡片字段：**

- 脱敏或完整单号按客户权限显示。
- 当前状态文字和图标。
- 最新事件摘要。
- 取得时间和最近有效更新时间。
- 结果新鲜度：最新、沿用旧结果、暂未获取。
- 所属操作/批次。
- 查看详情按钮。

**批量操作：**

- 选择结果后可执行“加入分组”“导出”“检查更新”。
- “检查更新”只创建符合服务端规则的检查任务，不承诺立即访问上游。
- **“检查更新”弹层默认勾选异常与暂未获取项**（未找到、异常、投递失败、退回、暂未获取）——最常见的重查动机不需要每次手点；勾选面板实时显示“将检查 N 条 · 其中终态 X 条将自动沿用（不发起查询）”，默认勾选可修改。
- 终态、30 天内刚检查过或服务端判定不需要重新查询的项目，应在操作确认中说明“将沿用现有结果”，不能假装重新查询（对应 07 §3.8 第 3 步库匹配细则）。
- 无选择时批量按钮禁用；批量操作提交后显示作业 ID和进度入口。
- 破坏性操作（删除组、删除批次等）一律二级确认，确认弹窗内提供“先导出备份”快捷入口，删除后进入可恢复期（§5.8）。

### 5.7 单号详情

详情页采用“当前摘要 + 完整轨迹 + 元信息”结构：

**摘要卡：**

- 单号。
- 当前状态文字。
- 状态更新时间。
- “检查更新”按钮。
- “加入分组”“返回结果列表”按钮。

**轨迹时间线：**

- 按时间倒序或正序统一呈现，默认最新事件在上方。
- 每条事件显示状态、原文摘要、地点、原始时间、客户时区时间。
- 轨迹翻译作为增强入口：可切换显示中文译文；译文不能覆盖原文，必须标注“机器翻译，仅供理解”，事实字段仍以原文为准。接口未开放翻译前不展示该按钮。
- 时间置信度不足时显示“时间按来源原文记录，时区可能需要确认”。
- 旧结果沿用时在摘要卡和时间线顶部同时显示“沿用已有结果”和最近有效更新时间。

**异常状态：**

- 暂未找到：说明系统暂未取得可展示结果，不等于确认包裹不存在。
- 暂未获取：说明任务仍在排队、等待重试或被服务暂停，不显示内部原因。
- Provider 暂停：显示“查询服务暂时不可用，已提交任务会保留；请稍后查看”，不提供换出口、重复提交或加快请求建议。
- 模拟数据：仅开发/验收环境允许出现，使用醒目标签“模拟数据，仅用于测试”，不得使用正常真实结果的视觉样式隐藏标签。

### 5.8 组与批次

- 客户可以创建、重命名、归档自己的“目标组”；每次提交后系统自动建立一个可改名的“默认组”，该批次自动归入默认组。
- 组列表显示名称、单号数、批次记录、最近更新时间和最近状态分布；组内可继续打开每个历史批次。
- 批次详情显示来源、提交时间、总量、已完成、处理中、暂未获取、失败待处理和扣费摘要。
- 删除组只删除客户侧组织关系，不删除全局事实、批次历史或账务记录；危险操作必须二次确认并说明影响。
- 批次页面提供“继续查看结果”和“导出当前批次结果”入口，导出进入导出任务，不生成无期限下载按钮。

### 5.9 提交记录、导入任务与导出任务

提交记录展示：

- 操作 ID。
- 创建时间。
- 总条数与批次数。
- 操作状态。
- 实际扣费。
- 最近更新时间。
- 查看进度 / 查看结果按钮。

导入任务展示：

- 文件名、创建时间、总行数。
- 清洗进度、入队进度和完成进度。
- 成功、失败、跳过、重复数量。
- 失败行的白话原因，可下载失败明细。
- 与对应操作 ID、默认组和批次记录的关联入口。

导出任务展示：

- 导出范围：全部结果、当前组、当前批次或所选结果。
- 创建时间、处理进度和文件格式。
- 下载按钮及过期时间。
- 失败原因和重新生成入口。

导出文件使用短期有效下载链接；链接过期后显示“文件已过期，请重新导出”，不得显示服务器路径。

### 5.10 查询统计

查询统计只展示客户自己的历史汇总，不展示其他租户或内部 Provider 指标：

- 按时间统计提交次数、查询单号数、实际扣费和免扣数量。
- 按客户状态统计已签收、运输中、派送中、已揽收、未找到、异常等分布。
- 按批次和目标组统计最近操作趋势。
- 可导出当前时间范围的统计摘要；导出同样进入导出任务页。

统计口径由服务端返回，前端不得用当前页数据推算全量结果。

### 5.11 积分中心

积分中心至少包含：

- 当前余额。
- 处理中冻结积分。
- 可用余额。
- 套餐卡片：积分数、单价、总价、赠送说明。
- 消耗、充值、赠送、退款/冲正流水。
- 兑换码入口（如启用）。

提交页面只显示固定计费规则和提交返回的实际扣费，不在前端自行计算套餐价格或免扣规则。余额为 0 时仍允许查看历史结果和账户页面，但提交相关主按钮显示“积分不足，去积分中心”。

### 5.12 设置、使用指南与关于

设置页包含：

- 修改密码。
- 当前会话和退出其他会话（如接口支持）。
- 显示时区偏好。
- 结果列表默认排序偏好。

使用指南按任务组织，而不是只放几条常见问题：

- 怎么输入：手动粘贴、文件上传、分隔符、空行和重复行的处理方式。
- 提交与扣费：一次提交多少条、什么时候扣积分、30 天重复免扣、无效项为什么不扣费。
- 大批量：导入任务、批次、默认组和目标组分别是什么，如何查看进度和失败行。
- 查看结果：结果列表、状态标签、时间线、机器翻译和“沿用旧结果”的含义。
- 导出：导出范围、文件格式、下载有效期和导出任务。
- 检查更新：什么时候会真正检查，什么时候沿用现有结果。
- 账户：积分明细、套餐、兑换码、个人设置和安全设置。
- 异常：积分不足、超出上限、服务暂停、暂未获取和联系支持的方式。

帮助页不展示内部 Provider、代理、浏览器 profile、队列名、数据库或上游地址。

### 5.13 新手引导与状态图例

> 来源：FrogTracking 交互优化方案流程 4（解决"零 onboarding"问题，见 11 号文档 G2）。

- **首次登录 3 步引导**：提交一批（可填入示例单号）→ 查看批次进度 → 查看结果详情；每步可跳过，跳过与完成状态持久化，不打扰回头客。
- **示例数据不伪造**：引导中的示例单号与结果明确标记“示例”，正式环境不产生任何模拟轨迹（继承 §5.7 模拟数据红线）。
- **双状态常驻图例**：任务状态（已受理/查询中/已获取/暂未获取）与物流状态（签收/运输中/…）是两套概念，在筛选栏旁提供 ⓘ 悬浮图例卡，比让客户读帮助文档有效。
- **空状态即引导**：每个空页面说明“为什么为空”并给出下一步动作（§7.3），如空查询组显示“去提交第一批单号”。
- 引导文案不承诺完成时间、不承诺查询成功率、不出现内部术语（Provider、队列、批次切片等）。

## 6. 核心交互流程

### 6.1 快速查询流程

```text
首页粘贴单号
  → 未登录：保存输入并登录
  → 已登录：进入临时快查
  → 点击开始查询（同一 client_request_id 可安全重试）
  → 服务端一次完成清洗、计费、入队
  → 返回 202、操作 ID、实际扣费与分类汇总
  → 订阅进度 / 退避轮询
  → 展示结果卡或暂未获取状态
  → 可进入详情、默认组和参考记录
```

### 6.2 批量提交流程

```text
粘贴文本或上传文件
  → 前端显示输入保护和费用规则
  → 点击开始查询
  → 服务端事务完成清洗、计费资格锁定、扣费和入队
  → 返回 202、操作 ID 和实际扣费
  → 自动归入默认组并按批次聚合展示进度
  → 已完成结果可先看，其余继续处理
  → 完成/部分完成/暂未获取
  → 可从批次生成导出任务
```

### 6.3 结果更新流程

“检查更新”只表达客户希望检查，不表示立即访问 USPS：

1. 客户选择单号并点击“检查更新”。
2. 前端调用本站允许的更新接口。
3. 服务端根据终态、30 天窗口、最近查询时间、队列和 Provider 健康状态决定是否创建任务。
4. 前端显示“已提交检查”或“沿用现有结果”。
5. 结果通过 SSE 或只读轮询更新；后台静默保鲜的新事实只在客户再次读取时呈现，不主动改动当前页面行状态。

这一流程落实「客户触发式呈现」：fresh 命中、终态沿用和服务暂停都返回可理解状态，前端不得把沿用旧结果伪装成刚查过，也不得因轮询自动创建更新任务。

## 7. 状态、加载和异常设计

### 7.1 客户可见状态字典

| 状态 | 颜色/图标之外的固定文案 | 客户动作 |
|---|---|---|
| 提交已受理 | 已收到你的请求，正在安排查询 | 查看进度 / 离开页面 |
| 查询中 | 正在查询，结果会逐步更新 | 等待 / 查看其他记录 |
| 已获取结果 | 已获取结果 | 查看详情 / 检查更新 |
| 已获取结果（沿用旧结果） | 当前展示的是已有结果 | 查看更新时间 / 稍后检查 |
| 暂未获取 | 暂时还没有可展示结果 | 稍后查看 / 查看失败说明 |
| 服务暂时不可用 | 查询服务暂时不可用，已提交任务会保留 | 稍后查看 / 联系支持 |
| 账户只读 | 当前账号暂时不能提交新查询 | 查看历史 / 联系支持 |

物流状态标签参考竞品并映射到服务端标准状态，前端只显示白话文案：已签收、运输中、派送中、到达待取、已揽收、已下单、未找到、异常、邮资未付、投递失败、退回。未知原文状态显示“其他状态”，不得由前端猜测归类；标签字典由服务端 `GET /api/v1/status-dict` 提供。

颜色只作辅助，必须同时显示文字、图标或状态标签。涨跌颜色规则不适用于物流状态。

### 7.2 加载状态

- 首次加载：显示页面骨架或“正在加载”，不显示空数据提示。
- 操作提交中：主按钮显示进行中状态并禁止重复点击。
- SSE 重连：顶部显示轻量“正在恢复进度连接”，不遮挡已取得结果。
- 轮询中：显示下一次自动检查的说明，不显示高频倒计时诱导客户反复点击。
- 文件处理：显示作业进度和可离开页面提示。

### 7.3 空状态

空状态必须说明“为什么为空”和“下一步做什么”，例如：

- 无查询记录：开始一次查询。
- 无筛选结果：清除筛选条件。
- 无积分流水：完成首次充值或使用试用额度。
- 无导出作业：从结果列表选择记录后导出。
- 无分组：创建分组或从结果列表加入分组。

### 7.4 错误状态

错误文案只使用客户可理解的结果：

- 网络暂时不可用：保留当前输入，提供“重试”。
- 登录失效：重新登录，保留草稿。
- 余额不足：去积分中心，保留当前输入。
- 超出单次上限：删减后重试或拆分提交。
- 文件格式不支持：说明支持格式，保留当前输入。
- 服务端校验失败：显示白话原因，不扣费、不创建操作。
- 操作重复提交：打开已有操作记录，不重复扣费。
- 无权限：返回工作台，不暴露资源是否存在。
- 服务暂停：保留任务，稍后查看。

内部 `403`、`429`、挑战、代理、Worker、队列和解析器错误统一由后端映射为上述客户文案。

## 8. 异步进度与恢复交互

### 8.1 进度展示

大批量任务展示：

- 总数。
- 已完成。
- 查询中。
- 已获取结果。
- 暂未获取。
- 失败待处理。
- 当前批次 / 总批次。
- 最近更新时间。

进度条只表示服务端已确认的投影进度，不根据前端计时器自行增长。最多 1,000,000 条提交按并发环境数均衡分批（环境数由服务器内存自动推算）；这是进度显示粒度，不承诺同时启动相同数量的上游查询。

### 8.2 SSE、断线与多标签页

- 首次打开操作详情：先读取 operation snapshot，再订阅 SSE。
- SSE 事件使用持久化 `projection_event_seq`；重连携带 `Last-Event-ID`。
- 发生序号缺口、事件过期或权限变化时，重新读取快照再继续订阅。
- SSE 不可用时进入 15–30 秒退避的只读轮询；轮询不会新建任务或扣费。
- **可见性感知轮询**：标签页不可见时暂停轮询与 SSE 心跳；恢复可见时先拉轻量版本号/快照摘要，有变化才拉全量数据——后台标签页不浪费请求，前台标签页不错过更新。
- **连接状态指示器**：顶栏常驻小圆点，实时（SSE）/轮询/离线三态，离线时不遮挡已取得结果。
- **变化感知**：状态跃迁的单号卡片以强调色描边高亮 1.2s 后淡出，列表顶部插入“N 个状态更新”摘要条；翻页不打断更新流，更新计数徽章挂在筛选栏，用户翻完页可一键跳到“已变更”的记录。
- 同一账号多标签页只读订阅同一操作，不重复提交；一个标签页的提交结果可以被其他标签页通过快照发现。
- 离开页面不取消后台任务；明确取消能力若未由后端提供，前端不得展示“取消”按钮。

## 9. 响应式、可访问性与性能

### 9.1 响应式规则

- 桌面端：左侧工作台导航、顶部账户栏、主内容区三层结构。
- 平板端：导航可收起，摘要卡由四列降为两列。
- 手机端：导航改为抽屉或底部入口；摘要卡单列；表格转换为卡片；主按钮固定在内容末端，不遮挡输入。
- 长单号、操作 ID、错误追踪号使用可换行等宽字体；不得因不换行撑破页面。
- 100 万行输入和结果列表使用虚拟滚动或分页，禁止一次性渲染全部 DOM；SSE 只按批次聚合刷新，不逐行推送。
- 页面最小高度使用 `min-height: 100dvh`，不依赖固定 `h-screen`。

### 9.2 可访问性

- 所有输入框有可读 label 或等效无障碍名称。
- 键盘可完成输入、提交、筛选、打开详情和关闭弹窗。
- 焦点顺序与视觉顺序一致；弹窗打开后焦点进入弹窗，关闭后返回触发按钮。
- 加载、错误、提交成功和服务暂停使用 `role="status"` 或 `role="alert"`，避免只用颜色或动画传递信息。
- 支持 `prefers-reduced-motion`；减少进度动画、闪烁和自动滚动。
- 触控按钮满足可操作尺寸，危险操作需要明确二次确认。

### 9.3 性能与隐私

- 不把输入内容发送到第三方分析、广告或外部 AI 服务。
- 客户端只调用本站 `/api/v1/*` 白名单。
- 不生成 source map，不输出生产调试日志。
- 长列表采用虚拟列表、分页或窗口化渲染；输入框更新不得导致整页重绘。
- SSE 连接、轮询定时器、窗口事件和上传任务在组件卸载时必须清理。

## 10. 前端状态机与接口约束

### 10.1 提交状态机

```text
idle
  → editing
  → submitting
  → accepted
  → tracking
  → completed / partially_completed / temporarily_unavailable
```

允许的异常回退：

- `submitting → validation_error → editing`（未产生操作，不扣费）
- `submitting → insufficient_points → editing`（保留输入，去积分中心）
- `submitting → idempotent_replay → accepted`
- `tracking → disconnected → snapshot_reload → tracking`
- `tracking → temporarily_unavailable → tracking`（任务保留，不重复提交）

前端不得从 `submitting` 直接跳到 `completed`，不得从 `temporarily_unavailable` 自动跳到成功，也不得通过刷新页面绕过状态机。

### 10.2 接口使用原则

- 客户侧只有一步提交：前端提交原始输入和 `client_request_id`，不接受前端传入的积分、金额、余额、免扣结果或收费分类。
- 服务端在同一次请求内完成清洗、计费资格锁定、扣费、入队和事务落库；返回 202 时同时返回实际扣费、免扣、重复和不可计费数量。
- 网络重试必须复用相同 `client_request_id`；同键返回原响应，不得创建第二个操作或第二次扣费。
- 所有列表、详情、进度和导出接口都必须由服务端按当前客户身份过滤。
- 前端只依赖 09 模块定义的字段和错误码；不读取数据库字段、内部日志或未公开接口。

## 11. 模块间依赖

- 依赖 03 管理员后端提供客户 API、账户状态、管理配置和权限结果。
- 依赖 05 数据模型与数据库模块提供投影、事件、快照、结果、批次和作业数据。
- 依赖 06 提交清洗与积分计费模块提供直接提交、清洗、计费、余额、免扣窗口、幂等和退款/冲正语义。
- 依赖 07 任务调度并发与限流模块提供异步进度、服务暂停、重试和熔断后的客户可见状态映射。
- 依赖 08 测试发布与运维模块提供构建、黑名单、响应式、性能和端到端验收环境。
- 依赖 09 接口契约权限与安全模块提供 HTTP/SSE、错误码、鉴权、租户隔离、安全响应头和越权规则。

## 12. 交付内容与验收标准

### 12.1 交付内容

- 公共首页、产品、套餐、登录、试用、帮助和关于页面。
- 客户工作台、提交、临时快查、结果列表、详情、组与批次、提交记录、导入导出、积分中心和设置页面。
- 竞品参考的首屏快查、默认组/目标组、批次记录、状态汇总、筛选、批量操作、轨迹翻译入口、查询统计、积分明细、详细使用指南和异步作业交互。
- 直接提交 → 202 → SSE/轮询 → 结果展示的完整前端状态机。
- 加载、空状态、错误、余额不足、超出上限、部分成功、服务暂停、会话失效和断线恢复的页面状态。
- 桌面、平板、手机三档响应式布局，键盘操作和减少动效支持。
- 设计系统（Design Tokens）落地：中性灰阶 + 单强调色、数据列等宽字体、两级阴影、120–200ms 微交互与密度切换（§4.4）。
- 实时解析面板、成本预估条、大批量防呆确认、“检查更新”默认勾选异常态、状态跃迁高亮与变更摘要条、可见性感知轮询、连接状态指示器和新手引导（§5.4/§5.6/§5.13/§8.2）。
- 客户前端黑名单扫描、无 source map、无外部数据源引用和长列表性能实现。

### 12.2 验收用例

1. 未登录客户从首页粘贴单号，登录成功后输入内容仍保留并可直接提交。
2. 空输入、超长输入、超出单次上限和多行输入均有明确反馈，不静默截断。
3. 首页和提交页没有独立“预览/报价确认”按钮；点击“开始查询”即提交。
4. 提交成功后返回实际扣费、免扣、重复和不可计费数量；提交失败且未产生操作时不扣费。
5. 提交返回 202 后显示操作 ID、默认组和“已受理”，不伪造行级物流结果。
6. 网络重试使用同一幂等键，不重复扣费、不重复创建操作。
7. 余额不足、超出上限、文件格式错误、无权限和会话失效均显示白话文案和下一步动作。
8. SSE 断线、序号缺口和事件过期时能恢复快照；轮询不会重复扣费或创建任务。
9. 批量任务能显示总量、批次、已完成、处理中、暂未获取和服务暂停。
10. 结果列表支持筛选、批量选择、分组、导出和检查更新；终态与沿用旧结果有明确标记。
11. 单号详情显示状态、完整事件、地点、原始时间、客户时区时间和时间置信提示。
12. 开发/验收模拟数据始终显示模拟标记；正式客户页面不得出现模拟轨迹。
13. 移动端不出现核心内容横向溢出，长单号可读，键盘和焦点操作正常。
14. 生产构建不含 USPS 上游域名、代理、Provider、profile、内部地址、secret、调试日志或 source map。
15. 后台静默保鲜写入新事实后，当前页面不自动改行、不弹通知；客户点「检查更新」后才显示最新结果。
16. fresh 命中时仍显示完整检查反馈，但不出现「下次自动更新 X」「查询次数」「重试次数」，文案不暗示已访问 USPS。
17. 提交页实时解析面板与成本预估条的数据全部来自服务端预估接口（防抖调用），前端无本地计费逻辑；预估条常驻“预估，以提交结果为准”标注。
18. 超过 1,000 条或非默认组提交先出现防呆确认卡（目标组/条数/预估积分），确认后才提交；确认卡不产生报价、不计费、不入账；小批量默认组提交不弹。
19. SSE 推送状态跃迁时，对应卡片高亮淡出并出现“N 个状态更新”摘要条；翻页不打断更新流，可一键跳到“已变更”。
20. 标签页不可见时轮询与 SSE 心跳暂停，恢复可见后能补齐期间的变更；顶栏连接状态指示器正确反映实时/轮询/离线三态。
21. “检查更新”弹层默认勾选异常与暂未获取项，并实时显示“终态 X 条将自动沿用”；首次登录引导可完成、可跳过，示例数据带“示例”标记。
