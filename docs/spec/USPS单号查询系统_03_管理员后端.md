# USPS 单号查询系统 03：管理员后端

> 管理端独立域名：`pandaadmin.ginzavog.com`。该域名与客户前端 `pandatrack.ginzavog.com` 分开配置 DNS、TLS、Nginx 服务块、Cookie 范围和登录会话，不共用入口。

## 1. 模块目标

为内部运营和运维人员提供受控的客户、积分、Provider、任务队列、审计和运行状态管理能力。管理员后端通过独立域名 `pandaadmin.ginzavog.com` 访问，仅限内网、VPN 或来源白名单等受控通道，不作为客户功能，也不直接绕过业务 API 修改数据库事实。

## 2. 功能范围

- 管理员身份认证、角色授权、会话和访问审计。
- 客户/租户/席位/账号状态管理。
- 套餐、积分增减、兑换码批次、冲正和账务核对。
- 操作、批次、任务、Provider 健康、熔断、失败队列和 A/B 投影延迟的只读观察。
- 退款审批、Provider 开关和维护操作的受控流程。
- 系统审计日志和管理操作导出。

不包含：客户页面（04）、实际 Provider 采集（02）、清洗和积分算法（06）、直接编辑 A 库采集事实或 B 库账务流水。

## 3. 关键设计

### 3.1 权限模型

使用角色与权限点组合，至少分为只读运营、客户支持、账务操作、Provider 运维、系统管理员。高风险操作要求二次确认并记录操作者、对象、理由、前后状态、关联 operation/job ID 和时间。生产管理员不得共用开发账号；管理员会话使用短时效和强认证配置。

**落地（R9，2026-11-19）**：权威矩阵 `apps/api/src/api/authz.py`，5 角色 code 为 `readonly`（只读运营）/ `support`（客户支持）/ `finance`（账务操作）/ `provider_ops`（Provider 运维）/ `super_admin`（系统管理员）。权限点：`customers:read/write/delete`、`billing:read/write`、`providers:read/write`、`audit:read`。规则：fail-closed（未声明角色一律拒绝）；`customers:delete`（注销）仅 super_admin；路由用 `require_permission` 强制校验，admin 前端按同一矩阵控制菜单与按钮可见性（服务端仍为权威）。legacy `admin` 角色由迁移 b/0006 归一为 `super_admin` 并加 CHECK 约束。登录防爆破（R10）按两级 key（`ip|账号` / `*|账号`）计数，10 分钟窗口失败 ≥5 次指数锁定（30s→1h），持久化 `auth_throttle` 表。

### 3.2 客户和账务操作

客户冻结/恢复通过业务服务写入；积分调整只能追加 `PointsLedger` 调整/冲正记录，不直接 patch 钱包余额。兑换码创建、导出、核销限制和失效均有审计轨迹。账务页面只读展示流水来源、reservation 和 operation 关联，人工处理通过受控命令/API执行。

### 3.3 Provider 与任务运维

展示 Provider 当前启用状态、最近真实成功时间、成功率、延迟分位数、拒绝/挑战/额度事件、熔断状态、解析失败、队列深度和最老任务年龄。Provider 启停仅允许对已验收配置操作；没有验收记录或处于停止状态时禁止启用。访问拒绝触发后，界面提供查看脱敏证据、熔断状态和显式重排死信任务功能；确属代理出口故障时，系统自动轮换到新出口 IP 并重试，不提供“一键批量换 IP/提高并发”操作。达到重试上限或熔断半开仍失败时 Provider 自动停止并生成报告。

任务重试必须验证错误类别、租约状态、重试预算和幂等键；不得重放已经成功写入的事实或重复计费。死信任务的批量重排必须有理由和结果记录。

客户误封解除、熔断自动复位、Provider 重新启用和死信批量重排均属于高风险操作：必须复核脱敏证据、写明原因、记录审批人和时间，且恢复后从最低已验证速率开始观察。系统故障导致整批 0 结果时，冲正/退款只能追加唯一流水并关联 operation，不得直接改钱包余额；客户自身提交的 `not_found` 不退积分。

### 3.4 安全

管理端使用独立域名 `pandaadmin.ginzavog.com`，不对公网自由访问；入口限制为内网、VPN 或来源白名单，Nginx 与该域名的 TLS、Cookie 范围和会话独立配置。后端再次校验角色、租户范围和操作权限。危险参数使用服务端白名单，不接受客户端传入任意 SQL、文件路径、shell 命令或 Provider endpoint。管理端不显示密钥、Cookie 或完整客户单号；必要标识脱敏。

## 4. 模块间依赖

依赖 01 的内网入口和秘密管理；依赖 05 的客户、账务、任务、Provider 状态数据；依赖 06 的积分和退款服务；依赖 07 的队列、Worker、熔断和监控接口；依赖 09 的权限与 API 契约。

## 5. 交付内容

- 管理员 API 与权限矩阵。
- 客户/租户、积分/兑换码、Provider/任务、审计页面。
- 高风险操作确认、幂等和审计实现。
- 角色越权、账务重复调整、Provider 未验收禁启用和死信重放测试。
- 内网访问与脱敏检查报告。
