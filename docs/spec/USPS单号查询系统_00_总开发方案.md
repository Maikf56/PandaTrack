# USPS 单号查询系统 00：总开发方案

> 状态：当前总入口与总技术路线。具体施工规格按 01–09 模块执行；本文件只保留全局目标、架构基线、跨模块约束、依赖顺序和总验收项，避免把模块细节重复写在这里。

## 1. 项目定位

### 1.1 产品目标

本系统是面向用户自己客户的真实 USPS 物流跟踪工作台，目标是让客户通过网页提交 USPS 单号，系统从 USPS 官方查询页面取得真实状态和物流事件，经过解析、存储和投影后展示给客户。费用定位为系统维护与运行成本，积分只作为用量计量和结算方式，不表示出售 USPS 数据或物流轨迹。

客户生产结果必须来自已经在目标 Linux 云服务器上完成真实样本、完整解析、稳定性、停止条件和容量验收的 USPS Provider。

已定事项：主数据源只保留 USPS 官网网页（不考虑任何的API接入）。

### 1.2 运行环境

- 已购 Linux 云服务器：当前唯一主要代码落地、开发联调、Linux 测试、真实 Provider 验收、并发压测、恢复演练和运行观测环境。
- Linux 生产：只部署通过验收的固定制品。可以是独立生产实例，也可以是完成清理和切换检查后的服务器生产区。

## 2. 全局功能范围

### 2.1 客户侧

- 客户登录、会话失效、客户/租户隔离。
- 单号粘贴/上传、服务端一次完成清洗、计费、受理和入队；客户侧没有独立预览步骤。
- 单次最多接收 1,000,000 个单号；后台分批按服务器的并发环境数动态驱动：环境数由 `auto_max_environments()` 按可用内存推算，单号先按 USPS 单次上限 35 条切片，再把切片按环境数均衡分配（一个环境顺序处理多代标签页）。100 万是系统受理上限，不是同时查询量，也不是浏览器环境数。
- 查询进度、批次进度、单号状态、完整有效轨迹、更新时间和客户备注。
- 主动检查更新、历史操作找回、异步导入导出、积分余额和兑换码核销。

### 2.2 管理侧

- 客户、租户、账号、席位和权限管理。
- 积分套餐、兑换码、钱包流水、冲正和审计。
- Provider 状态、队列、Worker、熔断、错误分类、数据质量和运行指标观察。
- 备份、恢复、发布、回滚和故障处置由受控运维入口完成，不向公网暴露 admin。

### 2.3 采集侧

- USPS 官方查询页真实访问适配（ClawBrowser 指纹环境 + Socks5 轮换出口）。
- 浏览器运行时、profile、指纹、Cookie/LocalStorage、会话和代理会话的隔离管理；ClawBrowser 启动时自动检测出口可用性。
- 多环境×多标签页并发：环境数按服务器资源推算、每环境多标签页、代间换指纹出口、随机人类间隔；跨客户汇总去重 + 库匹配判定（终态直接调取、非终态 20 分钟新鲜窗口，07 §3.8）后按 35 切片分批。
- 页面响应/DOM 解析、状态标准化、事件解析、证据保存、事实写入和投影摆渡。
- Provider 超时、解析失败、403、429、挑战、额度和明确拒绝的分类，以及自动换 IP、换环境、回炉重查、冷却退避、熔断与最终停止的分级处理。

## 3. 总体技术架构

```text
客户浏览器
    │ HTTPS
    ▼
Nginx / BFF
    ├── B 库：客户、操作、钱包、积分流水、计费 reservation、客户投影
    ├── SSE：读取 B 库已提交投影事件
    └── 受限管理端点
              │ 请求表 / outbox / 单向摆渡
              ▼
      sync-agent / Scheduler / Redis Queue
              │
              ▼
      Provider Worker Pool
        ├── 独立浏览器环境与会话
        ├── USPS Web Provider
        └── 解析、校验、事实写入
              │
              ▼
    A 库：TrackingFact、TrackingEvent、FetchJob、页面证据、采集状态
```

全局技术路线：Python 3.12 + FastAPI/uvicorn 负责 BFF 和后台服务；PostgreSQL 16 作为持久事实源；Redis 7 作为队列 broker 和短期缓存；Vue 3 + TypeScript + Vite 负责客户端和管理端；采集执行后端为 ClawBrowser 引擎级指纹浏览器（唯一后端，裸内核 Playwright/Patchright 直连实测被拦，不作兜底），经 CDP 驱动并复用页面解析；网络为 udealproxy Socks5 住宅代理，一个环境 = 一套指纹 + 一个轮换出口（每次启动自动分配新 IP）；Nginx 负责 HTTPS 反代和静态资源；systemd 或等效受控服务管理 Linux 进程。

## 4. 权威划分与全局数据原则

- A 库是 USPS 采集事实权威：tracking、event、FetchJob、解析证据、采集 outbox。
- B 库是客户业务和账务权威：客户、操作、客户关系、钱包、积分流水、reservation、客户投影、B 库 outbox。
- Redis 不是账务或任务唯一事实源；Redis 丢失时按数据库中的 `pending / claimed / lease` 状态重建。
- A/B 不做假设存在跨库原子事务，使用请求表、outbox、版本号、事件 ID、payload digest 和幂等重放。
- 客户只能看到 B 库白名单投影，不能看到 USPS URL、代理、浏览器 profile、A 库表名、内部错误码或采集证据原文。

| 项目 | 当前基线 |

| 单次客户提交 | 最多 1,000,000 个候选，是系统受理上限，不是 USPS 同时查询量 |

| USPS 单次网页/API 批量事实 | 官网/API 资料显示最多 35 个输入；这是单次批量输入/交易上限，不是网页 QPS、安全并发或线性扩容承诺 |

| 费用说明 | 提交页只展示固定规则：1 个新单号扣 1 积分、30 天内重复免扣、无效项不扣费；实际扣费在提交结果中返回 |
| 提交 | 客户点击“开始查询”后，服务端一次完成清洗、计费资格锁定、扣费、入队和事务落库；B 库单事务写 operation、reservation、ledger、幂等记录和 outbox，成功返回 202 |

| 采集主网络 | udealproxy Socks5 住宅代理为默认采集出口，按 profile 绑定代理出口；用户名携带多区域轮换（覆盖代理服务的所有可用区域），每批随机选州，一个环境自动分配一个 IP，环境重启大概率自动换 IP；ClawBrowser 启动后检测出口：TCP 连通 → 延迟/可用性 → USPS 首页可访问，不合格在发查询前换出口；代理异常不静默直连，阻断后按 §5.2 自动换 IP/换环境/回炉 |
| 并发模型 | 采集后端为 ClawBrowser 指纹环境（指纹与出口 IP 地理位置一致（ClawBrowser 自动匹配））；环境数按服务器可用内存自动推算（`auto_max_environments`：`max(2, (可用内存MB-900)//550)`，无上限、配置越好并发越多；按此式 2G→2、4G→4、8G→12，原「4G→6」为文档笔误，见 11 号文档 D1 裁定），`USPS_MAX_ENVIRONMENTS` 显式设置时优先；每环境顺序处理最多 10 个标签页、每约 10 标签页插随机人类间隔（基数 2500ms × 0.6~1.4 抖动）、代间换指纹出口；多客户待查单号先汇总去重，再按库匹配细则（终态直接调取、非终态 20 分钟新鲜窗口，07 §3.8）过滤后按 35 切片分给环境 |
| 队列恢复 | PostgreSQL 状态可重建 Redis；Worker 先提交事实和 outbox，再确认消息 |
| 访问拒绝处理 | 403、429、挑战、额度耗尽或明确拒绝：按 §5.2 自动换 IP → 换环境 → 回炉重查；达到重试上限或熔断半开仍失败才终态失败，全程无人工介入 |
| 提交响应 | 「立即」= 立即受理、立即落库、按批次入队，不等于立即拿到抓取结果；≤1,000 条提交 P99 ≤200 ms，历史 1 万条受理实测 ≤2 s；当前 1,000,000 条受理 P95 ≤60 s 为目标观察值，须在目标 Linux 验收区标定；异步首结果 P50 ≤15 s / P95 ≤60 s 同样须实测 |
| 前端更新 | 后台静默保鲜，前端客户触发式呈现；不向客户推送物流状态、不弹通知、不自动改行；fresh 命中不产生上游请求。例外：本次提交/重查操作自身产生的新结果按批次聚合 SSE 同步输送（07 §3.8 第 5 步），客户在线即可看到进度与新增结果 |
| 刷新成本 | 活跃单号按 7 天窗口参与刷新，受全局每日刷新次数上限控制；W1 必须实测 `bytes_per_fetch`、活跃单号量和每日刷新次数，复核毛利为正 |
| 恢复目标 | 每日备份场景 RPO ≤24 小时、RTO ≤4 小时；WAL/PITR 未实测前不承诺 0 丢单 |
| 生产发布 | 只能使用已验收固定制品，不在生产机临时编译、改代码或装依赖 |

### 5.1 批次粒度的关系

`1,000,000 / 35 / 标签页 / 环境代 / 环境数`不是同一层的数，不能混用。分批始终由并发环境数驱动，不是固定条数：

| 名称 | 数值或公式 | 用途 | 与环境的关系 |
|---|---|---|---|
| 客户单次提交 | 1,000,000 | 一次操作最多接收的候选数，控制请求体、受理时间和客户体验 | 与环境数无关 |
| USPS 页面单次输入 | 35 | 真实页面一次最多可提交的输入事实（上游固定上限） | 一切切片的最小单位；100 万条至少对应 `ceil(1,000,000 / 35) ≈ 28,572` 次页面请求 |
| 页面请求批次（标签页） | 35 | 一次 USPS 页面查询的输入，一个标签页一次 | 环境内标签页顺序执行，每约 10 个标签页插一次随机人类间隔 |
| 环境代 | 10 个标签页 | 一套指纹 + 一个出口的处理单元 | 代内复用指纹出口、代间轮换出口与指纹；不是并发数 |
| 浏览器环境数（并发） | 由 `auto_max_environments()` 按服务器可用内存自动推算：`max(2, (可用内存MB - 900M底座) // 550M单实例)`；`USPS_MAX_ENVIRONMENTS` 显式设置时优先 | 同时活跃的环境，线程池大小 | 并行处理能力的唯一来源；切片按环境数均衡分配，环境数越多单批越小、并行度越高；100 万是受理总量，不是并发 |

分批算法：提交后先跨客户汇总去重（含库内近期查询），再按 35 条切片，然后把切片均衡分配给当前推算出的环境数（每个环境顺序处理多代标签页）。因此**环境数决定分批粒度**：2 环境时切片串行排队更长，5 环境时切片更分散、并行度更高，100 万条按实测速率排队、不瞬时并发。

并发始终受限于环境数，与受理总量无关。百万级受理必须采用流式清洗、原文引用、集合化计费判定和异步明细补写，不能把 100 万条明细塞进单个事务。环境数推算参数如需调整，必须同步修改 06、07、04 的拆分与展示逻辑，并重跑百万级受理和队列公平测试。

### 5.2 阻断处理机制

命中 403、429、验证码/挑战、额度耗尽或明确拒绝时，按以下自动流程处理，全程无人工介入：

1. **换 IP 重试**：立即弃用当前出口，轮换到新 IP，重建浏览器环境后重试该批。
2. **换环境重试**：同批连续换 IP 仍失败，则整批重新入队，分配到其它环境（不同指纹 + 不同出口）重查。
3. **回炉重查**：多环境轮换后仍失败的单号进入回炉队列，随下一轮批次重新分片查询。
4. **冷却退避**：遇到 429 或带 `Retry-After` 的响应，按提示时长退避；无提示时按指数退避拉长间隔。
5. **停止该批**：达到重试上限（`max_attempts`，默认 3）或熔断打开且冷却半开仍失败时，该批标记为终态失败；客户侧显示"暂不可用/稍后重试"，不返回模拟轨迹。已扣积分但未提供结果时按 06 冲正/退款规则处理。

熔断与恢复自动进行：连续失败达阈值（默认 30，`USPS_CIRCUIT_FAILURE_THRESHOLD` 可调）时打开熔断，冷却期（默认 10 分钟，`USPS_CIRCUIT_COOLDOWN_MIN` 可调）后自动半开放行一次探路，成功则复位、失败则继续熔断。轮换 IP 是采集主网络方案的基本能力，阻断后换 IP 是第一顺位的自动恢复手段。

### 7.3 关键路径与风险

- **关键路径**：M3 采集核心（ClawBrowser 调试 + Akamai 对抗）是最大不确定性，可能溢出到 M4/M5。
- **缓解措施**：M3 期间用真实样本持续验证，不通过则保持 fail closed，不影响 M1/M2 业务骨架交付。
- **依赖风险**：N1（域名/TLS）、N2（测试样本/代理凭据）未就绪会阻塞 M3 验收，需在 M1 期间并行准备。

## 8. 总验收项

- 真实 USPS Provider 在目标 Linux 云服务器可取得真实轨迹，状态和事件解析与页面一致；mock 不得替代。
- 服务器开发、验收和生产使用独立数据库、Redis、域名 Cookie 范围、凭据、profile、代理会话和数据目录。
- 1,000,000 条受理、按 35 切片并按并发环境数均衡分批、30 天计费窗口、双扣防护和断点续写通过并发测试；切片不被误写成浏览器环境数。
- 35 条批量事实被正确标注为上游单次批量限制，不被误写成安全 QPS；1/2/5/10 环境验证时每个环境有独立轮换代理出口，并形成可追溯容量基线。
- 403/429/挑战/额度触发自动换 IP、换环境、回炉重查的分级处理，客户只看到白话文案，管理员能看到脱敏诊断证据。
- A/B 投影、SSE 断线恢复、Redis 重建、Worker 强杀、备份恢复和回滚均有测试证据。
- 前端黑名单扫描不得出现 USPS 域名、代理、profile、A 库表、secret、内部错误码和采集端点。
