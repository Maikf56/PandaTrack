# USPS 单号查询系统 01：服务器、域名与基础环境

## 1. 模块目标

在已购 Linux 云服务器上建立可复现、可隔离、可恢复的开发联调与验收环境，为真实 USPS Provider 验收及后续固定制品发布提供目标运行平台。Windows 仅承担备份、部署材料保存和必要远程运维辅助。

## 2. 功能范围

- Ubuntu Server 24.04 LTS（Noble）主机基线、SSH、公网入口、防火墙和系统账号。
- 域名 DNS、TLS 证书、Nginx 反向代理和 HTTPS。
- Python 3.12、Node.js、PostgreSQL 16、Redis 7、浏览器运行时及锁定依赖。
- 采集运行依赖：ClawBrowser 指纹浏览器（clawctl 二进制、引擎级内核与指纹库，实测裸内核过不了 USPS 结果页，故为唯一执行后端）、udealproxy Socks5 住宅代理（host/port/多区域用户名/密码）。
- ClawBrowser 每次启动约写 500M 会话数据，须预留磁盘并配置会话目录清理（见 07）。
- 开发联调区、验收/压测区、生产区的服务、数据库、Redis、域名、秘密、profile 和数据隔离。
- 监控、日志脱敏、备份、恢复和环境切换准备。

不包含：业务页面功能、USPS 状态解析规则、积分业务逻辑、客户业务权限规则；这些分别由 02–07、09 定义。

## 3. 关键设计

### 3.1 环境分层

- 验收/压测区：独立 namespace、数据库、Redis、密钥和数据目录；使用固定版本制品开展 Linux 验收、真实 Provider 验收和容量测试。
- 生产区：仅运行通过验收的不可变制品；生产数据、凭据、浏览器 profile 和代理会话独立管理。与开发/验收并行时使用独立实例或节点。
- Windows：保存项目备份、部署材料、验收报告和恢复材料，不运行项目服务，不承担开发测试。

### 3.2 主机与网络

- SSH 使用公钥和来源限制；调整防火墙前先验证第二会话和云控制台救援路径。
- 公网只开放 HTTPS 和受控运维入口；PostgreSQL、Redis、admin、Worker 仅本机或受控私网监听。
- Nginx 负责 TLS、反代、静态资源和 SSE 禁止缓冲；提交接口 `client_max_body_size` 至少 64m，代理读写超时按百万级受理目标标定；BFF 再次强制 64 MiB 请求体、1,000,000 候选上限，超限整批返回 422 而非静默截断。
- 服务器规格按真实 Provider 的 CPU、内存、磁盘、连接数和浏览器进程实测确定，不把历史估算当容量承诺。

**域名分工：**

| 用途 | 域名 | 配置要求 |
|---|---|---|
| 客户前端 / BFF API | `pandatrack.ginzavog.com` | 公网 HTTPS 入口，客户登录、提交、结果和 SSE 均使用该域名 |
| 管理员后端 | `pandaadmin.ginzavog.com` | 独立 DNS、TLS、Nginx 服务块和 Cookie 范围；仅内网、VPN 或来源白名单可访问 |

两个域名不共用会话、不强跳到同一登录页；管理端入口不得出现在客户前端导航、产物或错误文案中。

### 3.3 运行时和秘密

- 锁定 Python/Node/PostgreSQL/Redis/浏览器版本及依赖摘要；不依赖系统全局依赖漂移。
- 配置模板入库，秘密由环境级受控注入；开发、验收、生产分别使用不同 DB/JWT/Cookie/Provider/代理/备份密钥。
- 日志不得记录完整单号、Cookie、代理凭据、客户邮箱和秘密；诊断材料脱敏并限制访问。

### 3.4 发布与恢复

发布区只部署 CI 或受控构建生成的固定制品，校验 commit、迁移版本和 SHA-256；禁止在验收/生产区编辑源码或临时安装依赖。备份加密并异地保存，恢复必须在隔离 Linux 环境验证。每日 pg_dump 的恢复目标按 RPO≤24 小时表述；更低 RPO 只有在 WAL/PITR 完成并实测后才能承诺。

## 4. 已吸收的技术文档要求

- `pg_dump` 主版本必须为 16，并在主机初始化和备份脚本中硬校验；Ubuntu 24.04 默认源已提供 `postgresql-client-16`，可直接满足该要求。历史 Ubuntu 22.04 默认只有 14.x 客户端，不能直接用于 PostgreSQL 16 备份；若实际落到 22.04 主机，仍须按已验证源单独安装 16 客户端。系统升级或换镜像后，初始化脚本必须重新校验并留证，不得因"系统自带"就跳过校验。
- Nginx 只做 HTTPS 入口和反代，BFF 监听回环地址；SSE 必须关闭代理缓冲并配置长连接超时；业务请求体硬限制仍由 BFF 强制。
- systemd 服务账号和凭据文件按 BFF、采集、摆渡职责分离；BFF 进程环境不得出现 A 库 DSN。
- 部署使用只读 release 目录和固定制品摘要，迁移采用 expand/contract；应用回滚不等于数据库回滚，数据损坏必须进入恢复流程。
- 备份恢复应先停写再执行内容校验；每日 pg_dump 只能支持 RPO≤24 小时，不得宣称 0 丢单。备份加密、异地副本、WAL/PITR 和自动回滚在完成实测前标记为未完成。
- 真实 Provider 验收前置资料不写入方案秘密：N1 为境外域名、HTTPS 证书与最终地域确认；N2 为 30–50 个真实 USPS 样本（含分组空格、全角、BOM、乱码、国际 S10 与校验位存疑样本）、有效的 ClawBrowser 授权与内核缓存、有效 udealproxy Socks5 凭据（host/port/多区域用户名/密码）、出口轮换配置。云服务器已购不等于上述资料已就绪。
- 代理出口验收：在目标 Linux 上覆盖代理服务的所有可用区域实测出口可用性——由 ClawBrowser 启动并加载 USPS 页面自然检测，加载失败即判该出口不可用并重建环境换新 IP。需在验收期标定可用池清单（不同区域信誉差异显著），不把任一区域写成长期可用保证。指纹由 ClawBrowser 根据出口 IP 自动匹配。

## 5. 模块间依赖

依赖 00 的架构和环境口径；为 02–09 提供 Linux 运行时、数据库/Redis、域名/TLS、秘密和隔离区；发布与恢复验收依赖 08。服务器未完成基础隔离前，不启用真实 Provider，不承载客户生产数据。

## 6. 交付内容

- 主机基线与环境职责清单。
- DNS/TLS/Nginx 配置及端口暴露检查报告。
- 运行时版本清单、锁文件和秘密注入说明。
- 开发/验收/生产隔离检查表。
- 监控、日志脱敏、加密备份和恢复演练证据。
